SAMPLE DATA. The Harborline field-service pages and the 20 questions are fictional demo material for this scorecard. They are not a customer result, a benchmark claim, or a production measurement.

Each row is the same golden set run under a different retrieval configuration. Recall@k is the fraction of expected source chunks that appear in the top k hits. MRR is the mean of 1/rank for the first expected chunk. Faithfulness asks whether the drafted answer stays inside the retrieved text. The offline judge drafts from the retrieved sentences. If those sentences do not contain the reference values, it appends the reference answer and counts the missing values as unsupported. That is a stand-in for a model that answers from memory when retrieval misses. It is not a claim about a hosted judge.

Run notes

  • Sample corpus: fictional Harborline field-service notes. Glossary sections repeat a question without the procedure value so a short result list can rank them above the procedure note. That is demo material.
  • Expected sources are chunk_id markers in those notes, not live database ids.
  • The mock judge scores whether reference values (numbers, codes) appear in the retrieved text. A glossary note can share the question wording and still fail that check.
  • Embeddings are hashed token vectors (mock). Set LLM_PROVIDER=nvidia and NVIDIA_API_KEY to call NVIDIA embeddings and the judge.
  • Local fixture mode does not start RAGFlow. It chunks the sample pages, ranks them with lexical overlap plus the embedding vector, and optionally applies the density rerank.
